# Velvet — متجر الكتب الإلكتروني

مشروع متجر كتب عربي باتجاه RTL، مبني باستخدام HTML وCSS وJavaScript وVite وSupabase. الملفات الأساسية التي ستعدّل تصميم الموقع ووظائفه هي `index.html` و`style.css` و`app.js`.

> **مهم قبل الإطلاق:** المشروع يحتوي على واجهة المتجر وربط قاعدة البيانات وسياسات الأمان والطلبات اليدوية وإثباتات الدفع. لا توجد بوابة دفع إلكترونية مدمجة؛ إنستاباي وفودافون كاش يعملان بتحويل يدوي ومراجعة صاحب المتجر. لا يمكن تأكيد الدفع آلياً من دون تكامل رسمي مع مزود دفع.

## 2) المتطلبات

- Node.js حديث (يفضل 20.19 أو أحدث، أو 22.12 أو أحدث).
- حساب Supabase ومشروع جديد.
- حساب استضافة مثل Netlify أو Vercel أو استضافة ثابتة تدعم Vite.

## 3) إعداد Supabase

1. افتح [Supabase](https://supabase.com/) وأنشئ مشروعاً.
2. افتح **SQL Editor**.
3. افتح الملف `supabase/schema.sql` وانسخ محتواه بالكامل إلى محرر SQL ثم اضغط **Run**.
4. من **Project Settings → API** انسخ **Project URL** و**Publishable key** (أو المفتاح العام القديم `anon`). لا تستخدم `service_role` في الموقع.
5. انسخ `.env.example` إلى ملف جديد اسمه `.env` في المجلد الرئيسي.
6. املأ القيم:

```env
VITE_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY
```

لا تضع أي مفتاح `service_role` في `.env` الخاص بالواجهة أو في GitHub. المفتاح العام مصمم للاستخدام في المتصفح، والحماية الفعلية تأتي من سياسات RLS والدوال الموجودة في قاعدة البيانات.

## 4) إنشاء حساب صاحب المتجر

1. شغّل الموقع محلياً وافتحه.
2. أنشئ حساباً عادياً باستخدام البريد المحدد لصاحب المتجر: `mariam@gmail.com`.
3. إذا كان تأكيد البريد الإلكتروني مفعّلاً، افتح البريد واضغط رابط التأكيد، ثم سجّل الدخول مرة واحدة.
4. افتح **Supabase → SQL Editor** ونفّذ الأمر التالي مرة واحدة بعد إنشاء الحساب:

```sql
update public.profiles
set role = 'owner'
where lower(email) = lower('mariam@gmail.com');
```

5. سجّل الخروج ثم سجّل الدخول من جديد. سيظهر زر **لوحة الإدارة** داخل نافذة الحساب.

صلاحية المالك لا يمكن للعميل منحها لنفسه من الواجهة؛ أمر الترقية أعلاه ينفذه مالك مشروع Supabase من SQL Editor. لا تضع كلمة مرور الحساب في أي ملف.

## 5) تشغيل المشروع على جهازك

من داخل مجلد المشروع افتح الطرفية ونفّذ:

```bash
npm install
npm run dev
```

افتح الرابط الذي يظهر في الطرفية، وغالباً يكون `http://localhost:5173`.

لبناء نسخة النشر:

```bash
npm run build
npm run preview
```

ملفات الموقع الجاهزة للنشر ستكون داخل مجلد `dist`.

## 6) التخزين والصور وإثبات الدفع

ملف SQL ينشئ حاويتين في Supabase Storage:

- `book-covers`: عامة للقراءة، والرفع والتعديل والحذف لصاحب المتجر فقط. تُستخدم لأغلفة الكتب وصور التصنيفات.
- `payment-proofs`: خاصة. يرفع العميل إثبات طلبه داخل مجلد مرتبط بمعرّف حسابه وكود الطلب الداخلي. يستطيع العميل وصاحب المتجر الوصول إلى الإثبات وفق سياسات التخزين، ويولّد الموقع رابط عرض مؤقتاً لصاحب المتجر.

الحد الأقصى المطبق في الواجهة وقاعدة التخزين 5 ميجابايت. أنواع الملفات المسموح بها صور محددة أو PDF لإثبات الدفع.

## 7) إعداد المتجر من لوحة الإدارة

بعد تسجيل الدخول كمالك افتح **حسابي → لوحة الإدارة → إعدادات المتجر**، ثم أضف:

- رقم واتساب بالصيغة الدولية دون علامة `+`.
- بيانات إنستاباي.
- رقم فودافون كاش.
- روابط فيسبوك وتيك توك وإنستجرام.
- سياسة الاستبدال والاسترجاع.

الحقول تبدأ فارغة عمداً؛ لا توجد أرقام دفع أو روابط افتراضية. إذا لم تضف بيانات طريقة دفع، فلن يعرضها المتجر للعميل. رقم واتساب يُستخدم لإنشاء رابط برسالة الطلب بعد إنشائه.

## 8) آلية الطلب والمخزون

- الحد الأدنى للطلب 100 جنيه بعد الخصومات.
- أقل من 100 جنيه: ترفض قاعدة البيانات إنشاء الطلب.
- 100 جنيه بالضبط: الدفع عند الاستلام فقط.
- أكثر من 100 جنيه: إنستاباي أو فودافون كاش فقط.
- الأسعار والمخزون يعاد التحقق منهما داخل دالة `create_order` في قاعدة البيانات، وليس اعتماداً على حساب المتصفح.
- يتم حجز الكمية بخصمها داخل نفس المعاملة التي تنشئ الطلب، لمنع بيع آخر نسخة لعميلين في الوقت نفسه. عند إلغاء الطلب من لوحة الإدارة، تعاد الكمية مرة واحدة.
- إثبات التحويل لا يعتمد تلقائياً؛ حالة الدفع تنتقل إلى المراجعة، ويعتمدها صاحب المتجر بتغيير حالة الطلب إلى **تم تأكيد الدفع**.

## 9) النشر على Netlify أو Vercel

### Netlify

1. ارفع مجلد المشروع إلى مستودع GitHub.
2. من Netlify اختر **Add new site → Import an existing project**.
3. اختر المستودع.
4. اجعل أمر البناء `npm run build` ومجلد النشر `dist`.
5. في إعدادات الموقع افتح **Environment variables** وأضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
6. أعد النشر بعد إضافة المتغيرات.

### Vercel

1. استورد مستودع GitHub في Vercel.
2. استخدم Vite كإطار العمل، وأمر البناء `npm run build` ومجلد الإخراج `dist`.
3. أضف متغيري البيئة نفسيهما في إعدادات المشروع.
4. نفّذ Deploy.

النشر يجعل الواجهة متاحة دون بقاء جهازك مفتوحاً. قاعدة البيانات والصور والحسابات تبقى في Supabase.

## 10) رفع المشروع إلى GitHub

```bash
git init
git add .
git commit -m "Create Velvet bookstore"
git branch -M main
git remote add origin YOUR_GITHUB_REPOSITORY_URL
git push -u origin main
```

تأكد أن ملف `.env` غير موجود ضمن الملفات المرفوعة. ملف `.gitignore` يستثني `.env` و`node_modules` و`dist`.

## 11) ما الذي يعمل في النسخة الحالية؟

- واجهة عربية RTL متجاوبة، مقدمة لافندر، وضع ليلي ونهاري محفوظ.
- قراءة الكتب والتصنيفات والمراجعات العامة من Supabase.
- إظهار «أضيف حديثاً» اعتماداً على `created_at` داخل View في قاعدة البيانات لمدة 7 أيام.
- عرض حالة المخزون للعميل دون إظهار رقم الكمية.
- تفاصيل الكتب، البحث، الفرز، التصنيفات، الخصومات.
- سلة ومفضلة محفوظتان محلياً، ومزامنة المفضلة مع الحساب بعد تسجيل الدخول.
- إنشاء الحساب وتسجيل الدخول والخروج واستعادة كلمة المرور وتحديث الملف الشخصي.
- إنشاء طلب آمن والتحقق من الحد الأدنى وطريقة الدفع والأسعار والمخزون في قاعدة البيانات.
- رفع إثبات الدفع الخاص أو إرسال رقم العملية.
- إنشاء محادثة مرتبطة بكل طلب وتحديث الرسائل عبر Realtime.
- مراجعات تتطلب شراء الكتاب، وتظهر للعامة بعد اعتماد المالك.
- لوحة إدارة للكتب والتصنيفات والمخزون والطلبات والمراجعات والمحادثات والإعدادات والتحليلات.
- تحديث إشعار الطلبات الجديدة عبر Supabase Realtime.

## 12) فحوصات ما قبل الإطلاق

بعد ربط مشروع Supabase وحساب المالك، جرّب عملياً:

1. إنشاء حساب عميل ثم تسجيل الخروج والدخول.
2. إنشاء كتاب من لوحة الإدارة ورفع غلاف له وربطه بأكثر من تصنيف.
3. التأكد من ظهور حالة المخزون فقط للعميل ومن ظهور الرقم الحقيقي للمالك.
4. إضافة كتاب للسلة وتجربة مبلغ أقل من 100، ثم 100 بالضبط، ثم أكثر من 100.
5. تجربة طلبين متزامنين على آخر نسخة والتأكد من رفض الطلب الذي لا تكفيه الكمية.
6. إرفاق رقم تحويل أو إثبات، ثم مراجعة الطلب وتأكيد الدفع من لوحة الإدارة.
7. إلغاء طلب والتأكد من إعادة المخزون مرة واحدة.
8. التأكد من أن حساب العميل لا يرى طلبات أو محادثات عميل آخر.
9. تجربة الموقع على الهاتف والكمبيوتر قبل الإعلان عنه.

**ملاحظة اختبار:** لا أستطيع الوصول إلى مشروع Supabase الخاص بك أو تنفيذ عمليات شراء فعلية دون بيانات الربط والصلاحيات الخاصة به؛ لذلك يجب تنفيذ الاختبارات الواقعية المذكورة بعد وضع مفاتيح مشروعك. لا تضع مفاتيح سرية هنا في المحادثة.
